# Test reliability and verification simplification — Implementation and leader control plan v1.0

Binding design: [SPEC](test-verification-spec.md). Use one existing branch `refactor/source-architecture` and one existing cumulative draft PR [#690](https://github.com/pumni/Sky-Auto-Player/pull/690), not a new branch/PR. ## 1. Authority and checkpoints

Owner authorizes the program, remote pushes on the specified branch and GitHub coordination, retains merge/release/physical-input authority. Leader owns design, scope, coverage and compatibility decisions, trade-offs, dependencies, runner changes, gate removals, acceptance and next dispatch. Implementation agent owns investigation, local reversible edits within an explicit dispatch, formatting/linting, tests, measurements, cleanup, evidence, push and handoff. Routine code details are delegated; material design ambiguity, unsupported feature/config, failure attribution, changes to acceptance criteria or policy must be escalated. Do not self-approve, reinterpret SPEC, skip gate, change limits, or continue to next package without explicit leader dispatch. No production credentials, release, deployment, physical input, main writes, side branch, extra PR, force push or history rewrite.

Use substantive work packages, not per-file microtasks. Intermediate local commits are fine; one complete handoff per package (or BLOCKED with evidence), no intermediate approval unless material decision needed. Leader reviews the exact pushed HEAD immediately without waiting for CI. Pending CI is not pass; source/local acceptance is not final merge acceptance. Preserve prior reviewed architecture and D23 scope. If origin moves unexpectedly, stop and report; do not overwrite or merge unreviewed changes. If an older CI run fails, bind to its SHA, do not conflate with new source.

## 9. Handoff and leader review contract

One GitHub issue comment per completed package:
- `TRn READY FOR LEADER REVIEW` or `TRn BLOCKED`; exact branch, authorized start, tested source, pushed HEAD and tree, clean/dirty status, PR and CI run link/current status.
- Deliverables, commits, changed/removed owners and all callers migrated, old-to-new test/guard/command mapping, explicit retained exceptions and why, raw evidence location accessible to leader.
- Exact commands/cwd/feature set/exit/count/duration, first failures/retries, baseline comparator, benchmark samples and constraints; source-only vs local vs hosted vs native qualification clearly distinguished.
- Deviations, decisions needed, unresolved risk, no unauthorized action; stop. No automatic next package.

Leader independently inspects exact diff, source/test oracle and raw logs, compares inventory and contracts, verifies dead-code removal, checks current CI without waiting. Verdict: ACCEPTED (source/local scope as stated), CHANGES REQUIRED with bundled corrections, or BLOCKED. Only leader dispatch authorizes next package. Final merge readiness separately requires exact-final hosted gates and owner decision.
