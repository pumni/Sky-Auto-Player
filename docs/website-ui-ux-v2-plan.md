## 3. Locked design specification

### 3.1 Foundations

Keep existing color palette and OKLCH fallback strategy. Palette anchors (fallback): page #07090d, quiet #0a0e14, instrument #111821, active #18212b, stage #202c37, text #f4efe3, secondary #b8b4ab, tertiary #92958f, gold #efca78, hover gold #f7dda2, info #b8ccd6, success #a9cbb7, warning #efb5a9. Preserve semantic roles, explicitly add only used roles for on-action, focus, interactive border and hover/pressed/selected where justified; decorative gold is quieter than actions. Test computed OKLCH and fallback contrast; adjust accessible role values if necessary within palette, report exact changes. Gold only for primary action/meaningful musical highlight. No gradient blanket or translucent card everywhere. Borders provide hierarchy, not decoration noise. No new light theme; support forced-colors and prefers-reduced-motion.

Keep Inter Variable body/UI, Playfair Display Variable for brand/narrative headings and system monospace only for actual timing/file/code data. Use sans for functional FAQ/guide headings. Body 16–18px, lead 18–22px, labels >=13px where meaningful; decorative >=12px except purely noninformational marks; documentation readable 65–75ch, line-height 1.6–1.75, links visibly underlined in prose. Hero title fluid 48–88px desktop range, allow ~36–48px on narrow mobile, locale-aware measure rather than forcing EN 9.5ch on VI. Verify actual Vietnamese font glyphs, line height, wrapping, text zoom. Keep fluid type tokens and no redundant font aliases after migration.

Spacing: keep existing 4/8/12/16/24/32/48/64/96/128/192 px primitives as needed, use semantic section roles; define only used tokens. Compact section each side ~32–64px, default ~48–96px, feature ~64–128px, product peak ~80–144px. Mobile use lower end. Max content width around existing 84rem; existing 12-column desktop and component container queries, stack by content when tight. Controls radius 6–8px, panels 12–16px; retain one primary elevation and quiet outlines. Avoid unneeded abstraction; no generic component factory, duplicate style sheets or new token layers just for naming.

Use CSS cascade order reset/tokens/theme/base/layout/patterns/components/utilities; retain only populated/needed roles. Use shared primitives/patterns for actual reuse (button/CTA, section intro, meaningful status, disclosure/link/callout) with consistent hover, active, focus, disabled where relevant. No clickable nonsemantic divs or nested interactive elements. Native anchors for navigation, buttons for actions. CSS transitions restricted to relevant properties; no transition: all.

### 3.2 Global shell and navigation

Desktop: brand, Overview, How it works, Guides, FAQ, GitHub link, EN/VI switch, primary release CTA. Overview links home top; How it works links existing #how-it-works; preserve #playback, #technical, #formats and legacy/public deep links. Use visible page/section context without misleading aria-current; route active state only where appropriate, no need for a scroll-spy if it adds complexity. Keep desktop sticky shell, test anchor offsets/focus and blur cost. Mobile: brand + compact visible release CTA + disclosure button; label compact but unambiguous, accessible name localized, 44px interaction target when possible, no clipping at 320px. Nav panel below header; non-modal disclosure, no focus trap; button toggles aria-expanded, Escape closes/restores focus when appropriate, outside click and link activation close, viewport changes reset state without hidden focus. No-JS nav participates in document flow and all links are accessible. No-JS enhancements only visible when initialized, not merely global .js. Mobile menu animation enter 200–240ms/exit 120–180ms with focus and hidden/inert behavior synchronized; use immediate fallback where browser support or reduced motion requires. Footer route-preserving locale switch (same page/guide where available), explicit links to Releases, Guides, FAQ, source, license and issues. Add lang/hreflang/accessible names for locale options where applicable; no auto redirect by browser locale.

### 3.4 Signature motion contract

One event model is source of truth for timestamp, elapsed position, keys, type and label; generate markup and derive state from it where possible. Preserve illustrative key mapping A1+B2+C3, D2, E3 if still pedagogically valid. Label clearly as slowed/schematic illustrative playback, not benchmark or game measurement. Timeline positions must correspond to the same model used for display, beginning at zero and ending at 100%, with an explicit hold interval if shown; choose one mathematically consistent illustrative duration scale and document it. Avoid fake absolute telemetry. State machine: idle/static, playing, paused (if provided), complete, stepped; minimal state set, no contradictory READY labels. Use one active marker, aria-current=step consistent with highlighted keys and timestamp, no stale static active class. Full 15-key visualization by default; responsive compact mode may omit nonparticipating keys only if clear that it is an excerpt and mapping remains understandable.

User-triggered Play/Replay and accessible previous/next event controls; no autoplay in V2 (initial static informative frame). No sound. During playback use monotonic elapsed time (performance.now/rAF or WAAPI with a single timeline); no independent drifting timers or permanent rAF loop. Playhead translate via transform across measured track width, linear timing; avoid animating left/top/width on every frame. Hold fill via scaleX; active key visual state and text readable (no 0.5 opacity on essential text). On replay/rapid input cancel old run; manual step cancels playback; hidden tab and reduced-motion preference changes stop animation and settle into valid informative state. Reduced-motion allows manual event stepping without motion, no autoplay; no-JS static complete content with no dead controls. Handle resize, pagehide and cleanup if needed, no global leaked timers/listeners; avoid client router. Live region concise discrete meaningful announcements, not every frame. Focus remains stable. Test first/last progress, chord simultaneous key state, hold, replay interruption, step mid-run, visibility, reduced-motion changes, no-JS and mobile. No infinite loops.

### 3.5 Motion system

Use existing tokens or refine to semantic roles: press 90–120ms, hover/focus 150ms, disclosure enter 200–240ms and exit 120–180ms, screenshot crossfade 180–240ms, decorative emphasis <=420ms. Default curve cubic-bezier(.2,.8,.2,1); entrance cubic-bezier(.16,1,.3,1); timeline linear. No overshoot in data/timing. Motion communicates cause, feedback or change, never blocks content. Avoid broad scroll reveal, parallax, background particles, scroll hijack, permanent glow, custom cursor or JS animation framework. No page transitions/ClientRouter in this scope. Prefer opacity/transform, measure necessary layout animation such as native disclosure; reduced-motion neutralizes spatial animation and never leaves hidden content. Test no-hover touch and keyboard states.

### 3.6 FAQ and Guides

FAQ: retain native details/summary, support EN/VI deep-link to closed answer (open target and ensure visible/focus as appropriate; no-JS behavior verified), meaningful summary target size/focus, visible mobile TOC via compact native disclosure or normal list; desktop sticky TOC bounded by viewport, scrollable if needed, current anchor indication optional. Group by user task where existing content warrants, preserve IDs. No search dependency or unnecessary client search for small collection. Guides hub: maintain existing category order and routes, clear user-task labels and links, version/date where verified and meaningful. Guide articles: breadcrumb, heading hierarchy, readable text, code/pre overflow local to code, lists/tables, visible inline links, reusable warning/note patterns only where used, heading anchors and TOC for genuinely long articles, related guides; mobile collapsible TOC, no floating obstruction. Keep Article/FAQ/Breadcrumb JSON-LD, canonical/hreflang, redirects, sitemap, llms/robots, site assets. Correct obsolete instructions in both locales at owning data/Markdown sources; no duplicate content or stale EN translation. Do not add search, new pages, theme toggle or route changes without lead approval.
