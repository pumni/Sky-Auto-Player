## Stable-source scope

Stable preparation may change only:

- version metadata from `3.5.0rc1` to `3.5.0`;
- the matching lockfile project version;
- stable release notes and acceptance documentation;
- changelog reconciliation from canonical published release notes.

No runtime, updater, dependency, toolchain, timing, or packaging changes are authorized for the stable source commit.

- GitHub ZIP digest == SHA sidecar == independent SHA256;
- external and packaged `MANIFEST.json` agree;
- version is `3.5.0`;
- `git_head` and native build commit equal the stable tag target;
- `dirty_worktree=false`;
- exact managed file set, sizes, and hashes pass;
- frozen version/native/Textual/optimize smoke passes;
- exact public `v3.4.5 -> v3.5.0` updater path passes;
- preserved user-owned paths remain unchanged;
- updater transaction/rollback/security matrix remains clean;
- Defender exact stable ZIP/tree/app/updater scans have no detection.

Interactive production `SendInput` is intentionally excluded from these mandatory stable gates by the owner waiver above.

## Publication rule

If every non-waived mandatory stable check passes, publish the existing stable Draft without rebuilding, retagging, replacing assets, or regenerating the manifest.

Final published state must be:

- `draft=false`;
- `prerelease=false`;
- `/releases/latest` resolves to `v3.5.0`;
- stable tag target unchanged;
- asset IDs and digests unchanged from qualification.

Any failure in a non-waived mandatory check is **NO-GO** and requires a new source fix/version as appropriate; do not mutate qualified release bytes.
