## 1. Goal and evidence

Clean, restrained, VS Code-inspired desktop preferences. Preserve all six categories (Playback, Appearance, Diagnostics, Updates, Donate, About), English UI, immediate native-authoritative persistence and accepted Graphite palette. Prefer flat setting rows, meaningful grouping, consistent label/description/control alignment and a single content canvas. No decorative dashboard/cards, gradients, glass, oversized graphics, extra search, reset/export, new settings window, new behavior or dependencies. Historical Settings captures in docs/ui/current (Appearance Light and three compact VQC scenes) predate the current shell commit; capture actual six categories in both modes before changes if feasible, label baseline SHA/tree. Diagnostics/Updates/Donate/About audit was source-led, not visual acceptance.

- Unified Settings shell and nav use bg-card, content pane bg-surface, one subtle 1px border and 8px radius; no extra nav right divider or border-y; 8px outer gutter and 8px gap, header 12px horizontal inset, content padding 20px wide / 12–16px narrow. One group separator before Donate only. Keep nav label and icon at compact widths; independently scroll nav only as required. Preserve existing navigation semantics (buttons + aria-current=page), category ordering and selection state across close/reopen; do not convert to tablist unless implementing actual tab keyboard model (not authorized). Category switch resets only content scroll to top, retains activated navigation focus; opening/reopening preserve existing initial focus/return focus behavior and never obscure focus. No remount entire modal.
- Category title 18/24 semibold, concise one-line description 12/18 where meaningful; section title 14/20 semibold, label 13/20 medium, secondary descriptions 12/18; use existing font stack and text semantic roles. Sections 20px apart, row gaps 12px, label-control gap 6px, optional divider only between meaningful groups; no nested cards per preference. Readout values tabular. Controls 36px normal, switch existing 36x20 with hit target; preserve existing compact 32px stepper and safe minimum targets. Use actual content container width, no new global breakpoint. Text wraps; trailing controls remain accessible; no clipping or ellipsis of critical values.
- No new color values or role table: existing --card/--surface/--popover/--border/--input/--selection/--accent-ink, foreground roles and primary; Graphite Dark shell #191A1B, canvas #121314; shared Light shell #F7F7F8, canvas #FFFFFF. Focus/control contrast on actual surfaces (normal text >=4.5:1, large >=3:1, essential control/state boundaries >=3:1 where applicable); preserve independent contrast oracle.
- Remove permanent native persistence footer. Keep error visible and announced even when content is scrolled or category changes, with human readable "Could not save settings." and appropriate detail; don't hide error on Donate/About if outstanding. Footer/status region only when needed, bounded and not obscuring focused controls. Use existing settingsState/settingsError; if showing Saving… use actual loading state while dialog open, no fake success or global disabling, no separate timer/state queue, no toast per toggle. Do not promise save if queued/failed; keep authoritative values. No retry button that replays stale patch; users can repeat action. Preserve serialized mutation semantics and rapid timing changes; do not change settingsSlice, preparation invalidation or native schema.
