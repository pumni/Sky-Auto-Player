## 2. Visual and interaction specification

Default Graphite target values (hex): background #121314, workbench #151618, card #191a1b, popover #242526, foreground #e2e4e8, secondary text #a6a8ad, muted text #94979e, border #2a2b2c, input boundary #72777d, primary #8e9dff, primary hover #a3b0ff, pressed #7888f0, primary foreground #11131a, accent ink/ring #9aa8ff, selection #222534, playing #1a1d28, success #64c496, warning #f5c451, danger ink #f27a80, destructive fill #c42b36/on #ffffff. Derive light and other palette role values from the existing themes.css at baseline, preserving their distinct identities; audit actual rendered pairs (WCAG 2.2 AA). Keep state contrast and forced colors; no hardcoded feature hex. If a palette pair fails, adjust the affected role minimally for contrast and report exact before/after; major palette changes require approval.
Typography: dialog 24/32 semibold; page 20/28 semibold; inspector song 18/24 semibold; section 14/20 semibold; body 14/20; dense controls 13/18; metadata 12/16; tabular numeric data. 4px spacing grid (4,8,12,16,20,24,32). Control radius 8, pane 10, popover 12, dialog 14; compact controls 28–32, standard 34–36, primary transport 42–44, no interactive target below 24x24 unless WCAG exception proven. Focus ring 2px with separation, no clipping. Keep dense geometry; use min-w-0, overflow and wrapping intentionally. Content hierarchy before decoration.

Layout: fixed top chrome, 3-pane flexible workbench, fixed bottom transport. Native window drag regions and caption controls must retain platform semantics; do not use custom SVG controls as substitute for native behavior. Expanded sidebar on wide windows, collapse from geometry policy only. Inspector docked when feasible, nonmodal overlay fallback at widths below dock threshold (browser-only at <800); no backdrop or focus trap for Inspector, independent scroll, cannot obscure dock. Preserve Escape, focus restoration, user widths and resize keyboard support. Avoid arbitrary breakpoint-driven geometry that disagrees with solver. No new settings fields in this campaign.

Surface requirements:
- Title bar: small approved logo and product name where space permits, scope-aware search, reload/update/settings icons with accessible tooltip and states; native drag and maximize unaffected. Search: input, clear, scope text, / and Ctrl+F; retain debounce/request ordering; visible results count and empty/failure/retry; do not turn scope-specific search into fake global search.
- Library: Built-in, Liked, Playlists with count, distinct selected state, compact accessible icon rail, create/import guidance when empty, playlist create/rename/delete and add/import files/folder/Built-in flows preserved. Delete confirmation explicitly distinguishes reference deletion from original files. Menus via Base UI; right-click context menu in WP2 only if existing actions can be reused without duplicate logic. No new sorting/command palette or backend features.
- Tracks: keep virtualized grid and pagination; preserve selection/playing independent (including simultaneous), row title truncation/tooltip, loading placeholders, errors, no results, like, add/remove and locate, keyboard navigation; no row remount animation or dynamic row height. Keep metadata accurate. Row action discoverability via selected/focused/hover state; keyboard reachability and pointer target. No fake album artwork, fake track count, or seek.
- Player: 3-column dock, stable center alignment, selected/now-playing title clarity, state text incl dry run/no input, auto play, shuffle, previous/next, play/pause/resume, stop and read-only progress. Native acknowledgement controls state; Stop immediate and available when contract permits. Profile popover keeps all real options including tempo, FPS, hold frames, timing margin, dry run, advanced; compact controls fit minimum. Do not add seek/volume not supported by engine.
- Admission and recovery: separate sheet conversion consent, timing-risk decision, focus/integrity/native gates; keep exact variant decision IDs and invalidation behavior. Human-readable headline, recommended vs current options with clear consequences, expandable technical details; no optimistic start or promise of in-game accuracy. Error/retry/status-unknown and stop recovery explicit. Warning/error cannot disappear just because toast times out. Focus must not cause accidental confirmation.
- Inspector: label Selected song distinct from Now playing; readiness first then format, pitch, track mode, conversion loss, risk rationale and recommendation, preserve every native option and consent. Keep Details and Runtime tabs and lazy diagnostics. Runtime Performance/Timing/Events; prioritized real metrics and explicit units, no data/dry run/disabled/stale/failure states; never fabricate metrics or waveform. Retain export.
- Settings: modal with categories Playback, Appearance, Diagnostics, Updates, Donate, About; keyboard nav and focus; preserve all settings and persistence errors. Appearance visual previews of actual mode/palette, no new preference persistence. No payment changes. Update dialog preserves real states and retry/install guards; progress determinate only if data exists; cannot bypass playback-active/update safety.
- Startup/error/loading: approved mark, clear message, no false progress; handle existing fatal/error boundaries. Empty states give one applicable action; skeleton matches layout, static under reduced motion. Toast only for noncritical success and recoverable feedback, deduplicate; use inline alert for blocking errors. Scrollbars discoverable on hover/focus/scroll and forced colors. No fake success or silently swallowed errors.
- Overlays: Base UI Dialog/AlertDialog/Popover/Menu/Select/Tabs/Tooltip/Switch/Collapsible as needed; actual registry implementation determines props. Use render composition, controlled value/open as needed, real portal lifecycle; no onPress adapter to mimic React Aria or duplicate focus trap. Keep modal Escape, focus restoration, outside-click policy and keyboard behavior based on function; nested overlays must work.

Motion contract (milliseconds): immediate 0; micro 80; fast 120; standard 180; panel 240; rare expressive 320 max. Standard cubic-bezier(.2,0,0,1); enter (.16,1,.3,1); exit (.4,0,1,1). Button/row hover 100–120 color; press 80 surface (optional scale .97 only noncritical action); like 150; transport icon crossfade 120 with fixed bounds; tooltip 100/80; menu 150/100; popover 180/120; dialog 200/140 + backdrop fade; inspector overlay 220/160 + translateX <=16px; tab indicator 150; switch/chevron 120–150; toast 180/120. Use Base UI data-starting-style/data-ending-style, transform origin and actual mount/unmount lifecycle, not React Aria data-entering/exiting. Honor prefers-reduced-motion: no nonessential displacement, scaling, spin or shimmer; static status remains. Avoid transition-all, perpetual will-change, expensive filters, per-row animation, animated geometry in resize or CSS-controlled playback timing. No artificial progress interpolation that outruns native state.
